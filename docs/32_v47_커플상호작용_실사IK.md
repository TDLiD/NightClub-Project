# v47 — 블루스 프로필 카드 · 커플 상호작용(실사 모델 기준 IK·충돌·손)

## 1. 블루스 중 프로필 카드
- 블루스를 추는 동안에는 부킹 상대 프로필 카드가 항상 떠 있지 않음. 마우스가 상대 몸(발~머리, 어깨 폭) 위에 있을 때만 보임.
- 대화만 할 때는 예전처럼 항상 표시. 터치 기기는 블루스 중 숨김.
- 파일: `service.js`

## 2. 원인 분석(v46까지)
- 커플 IK는 절차적 rig(관절 비율)로 계산하고, 실사 모델은 그 관절 회전만 복사.
  - rig와 모델의 팔 길이·어깨 위치가 달라 모델 손이 목표에서 어긋남.
  - 상대 몸 충돌은 rig 기준 타원체로만 검사해서, 실제로 보이는 모델 몸은 뚫림.
- 손: rig 손바닥 축(-Z)과 모델 손바닥(T포즈에서 아래)이 90° 어긋난 채 복사돼 손목이 비틀려 보였음. 손목 각도 제한도 없었음.
- 손가락: v46 매핑에 3ds Max Biped 손가락 이름이 없어 모델 손가락이 T포즈(쫙 편 상태) 그대로였음.
- 척추: rig 몸통 관절 하나가 모델 척추 뼈 1개에만 전달되어 허리 한 곳에서 꺾임.
- 실행 순서: 실사 모델이 커플 계산보다 먼저 갱신되어 한 프레임 늦은 자세가 보였음.

## 3. 바뀐 구조(기존 모듈 확장, 새 중복 시스템 없음)
| 역할 | 위치 | 내용 |
|---|---|---|
| 손 컨트롤러(HandPose) | `humanglb.js` `handCtl/applyHand` | 모델 손의 실제 축을 재서 rig 손의 손가락·손바닥 방향에 맞춤. 손목 한계: 굽힘·젖힘 65°, 비틀림 45°(쿼터니언 스윙-트위스트). 손가락은 마디마다 손바닥 쪽 굽힘 축으로만 접힘(옆으로 꺾이거나 뒤로 젖혀지지 않음), 엄지는 마주 보게 |
| 몸 충돌체(BodyCollision) | `humanglb.js` `capsules` | 실사 모델의 실제 뼈로 매 프레임 갱신. 몸통 좌우 2줄(골반 폭→어깨 폭), 목, 머리, 위팔, 아래팔, 허벅지 |
| 접촉점(ContactAnchor) | `humanglb.js` `RH.project` + `couple.js` | 손 목표를 상대의 실제 몸 표면 + 손 두께(2.2cm)로 옮기고 표면 법선을 구함. 얼굴 감싸기만 머리, 나머지는 몸통·목 기준 |
| 팔 IK(PartnerIK) | `couple.js` `ikArm` | 실사 모델의 실제 어깨 위치·팔 길이로 2관절 IK. 팔꿈치 145° 제한, 소프트 IK, 팔꿈치 방향(폴 벡터) + 스위블 탐색으로 상대 실제 몸을 피함 |
| 손 방향 | `couple.js` `handOrient` | 닿는 손은 손바닥이 상대 몸 쪽, 손가락은 아래팔 방향을 표면에 눕힌 쪽 |
| 몸통·머리 관통 보정 | `humanglb.js` `sepCouple` | 두 모델의 몸통·머리 캡슐이 1cm 넘게 겹치면 보이는 모델을 반씩 부드럽게 밀어냄(접촉은 허용) |
| 척추 분산 | `humanglb.js` | 모델 척추 3개에 45·30·25%로 나눠 휘게 |
| 발 디딤 | `karaoke.js` | 턴·돌아서기 중이거나 서로 당겨 거리가 빠르게 변할 때 제자리 걸음 |
| 실행 순서 | `humanglb.js` | 실사 모델 갱신을 모든 계산 뒤(프레임 끝)로 |

## 5. 남은 한계
- 모션 캡처 데이터는 넣지 않음. 커플 안무는 기존 절차적 타임라인 + IK. 전문 커플 모캡(블루스·슬로댄스)은 유료 에셋이 필요하고 상대 키에 맞춘 리타깃 작업이 따름.
- 발 IK(바닥 고정)·무게중심 계산은 근사 수준(제자리 걸음·무릎 굽힘). 발 미끄러짐이 조금 남을 수 있음.
- 소파·러브샷·꽃다발·편지·반지·커플 사진은 기존 소품·동작에 새 손 컨트롤러·손목 한계만 적용됨. 개별 안무를 새로 짠 것은 아님.
- 옷은 몸 텍스처에 붙어 있어 옷 자체 충돌은 없음(몸 캡슐로 대신함).
- 키 조합은 이번 측정에서 남 168 / 여 154 한 쌍만 실행. 다른 조합은 `tools/tests/couple_interaction_test.py`로 실행 가능.
