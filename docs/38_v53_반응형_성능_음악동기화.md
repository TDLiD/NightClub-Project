# v53 — 반응형·터치 최적화 · 적응형 성능 · 실제 음악 박자 동기화

v52를 기준으로 했습니다. 기존 기능은 하나도 지우지 않았고, 바뀐 곳은 아래 파일뿐입니다.

## 1. 먼저 한 일: 실측 점검(수정 전)
헤드리스 크롬으로 6가지 기기 조건에서 시작 화면과 게임 화면을 측정했습니다. 휴대폰·태블릿은 터치·모바일 UA·고밀도 화면까지 흉내 냈습니다.

| 기기 | JS 오류 | 가로 스크롤 | 화면 밖 버튼 | 겹침 | 작은 터치 영역(<36px) |
|---|---|---|---|---|---|
| 휴대폰 세로 390×844 | 0 | 없음 | 0 | 0 | **16개** |
| 휴대폰 가로 844×390 | 0 | 없음 | 0 | 0 | **17개** |
| 태블릿 세로 820×1180 | 0 | 없음 | 0 | **1**(상호작용 버튼 × 손님 배너) | **22개** |
| 태블릿 가로 1180×820 | 0 | 없음 | 0 | **1** | **22개** |
| 데스크톱 1366×768 | 0 | 없음 | 0 | 0 | 0 |
| 울트라와이드 2560×1080 | 0 | 없음 | 0 | 0 | 0 |

이 밖에 코드 점검에서 찾은 것:
- 데스크톱에는 적응형 해상도가 없었습니다(모바일 저화질만 있었음).
- 조명·LED·NPC 춤이 실제 음악과 상관없이 **고정 128BPM 시계**를 따랐습니다.
- 실사 인물을 기다리는 동안 손에 든 잔이 허공에 보일 수 있었습니다.
- 장면에서 빠진 임시 인물이 내부 목록에 계속 남았습니다(메모리).

## 2. 수정·추가 내용

### 터치·반응형 (`css/style.css`)
- 터치 기기에서 상단 아이콘, 음악 플레이어, 줌, 디스코·블루스·웨이터, 손님 목록 접기·닫기·필터·검색, 닉네임 추천, 대화 칩, 이모트, 모달 버튼을 **40~44px**로 키웠습니다. 휴대폰 가로는 40px입니다.
- 데스크톱(마우스)은 바뀌지 않습니다(`@media (pointer:coarse)` 안에서만 적용).
- 태블릿에서 손님 모드 배너를 상호작용 버튼 위로 올려 겹침을 없앴습니다.
- 휴대폰 세로에서 상단 아이콘 간격과 손님 목록 폭을 조정했습니다.

### 적응형 성능
- `js/gfx.js` **기기 등급**: GPU 이름(WEBGL_debug_renderer_info)과 메모리·코어 수로 등급을 정합니다(desktop-high / desktop-mid / desktop-low / mobile / mobile-low). 사용자가 화질을 직접 고른 적이 없을 때만 약한 내장 GPU·저메모리 PC의 기본값을 high → mid로 정합니다. `NC.device`에서 확인할 수 있습니다.
- `js/perf.js`(새 파일) **모든 기기 적응형 해상도**: 입장 6초 뒤부터 3초마다 FPS를 잽니다. 38fps 미만이면 픽셀 비율을 0.15씩 낮추고(최소 기본값의 60%), 56fps 초과가 3번 이어지면 0.1씩 다시 올립니다. 후처리 버퍼는 자동으로 다시 맞춰집니다. 계속 20fps 미만이면 화질을 낮추라는 안내를 한 번 띄웁니다. 모바일 저화질은 기존 `mobile.js` 방식을 그대로 씁니다.
- `js/humanglb.js`
  - 실사 모델을 입히는 속도: 모바일 1→2명, PC 2→3명(0.35초마다)
  - 대기 중에는 손에 든 잔·마이크도 숨기고, 장착하면 다시 보입니다.
  - 1분 넘게 장면에서 빠진 임시 인물은 목록에서 지웁니다.
- `js/realpick.js`: 모델 목록(매니페스트)이 6초 넘게 늦게 오면 생기던 오류(`playerPool` of null)를 고쳤습니다. 늦게 와도 도착하는 즉시 실사 캐릭터 선택 화면으로 바뀝니다.

### 새 기능: 실제 음악 박자 동기화 (`js/audio.js`, `js/world.js`)
- 재생 중인 MP3의 저음(40~180Hz)을 20ms마다 분석합니다. 스펙트럼 플럭스(저음이 갑자기 커지는 정도)로 킥을 찾고, 킥 간격의 히스토그램과 정밀 평균으로 BPM을 추정합니다. 그런 다음 박자 시계를 천천히 위상 고정합니다. 박자 번호가 튀지 않습니다.
- 박자 시계를 쓰는 **조명·레이저 패턴·LED 벽·NPC 춤·무대 댄서·커플 리듬**이 모두 실제 노래 템포를 따라갑니다. 해당 코드는 수정할 필요가 없었습니다.
- 조명 펄스 크기 = 실제 음악 세기(`NC.Audio.energy`).
- 조용하다가 확 터지는 순간에는 손님 환호(`music:drop`, 기존 반응 재사용)가 나옵니다. 최대 8초에 한 번입니다.
- 노래방은 곡마다 자체 박자를 써서 영향이 없습니다.
- **검증**: 헤드리스 브라우저는 소프트웨어 렌더링 때문에 메인 스레드가 포화돼(분석 호출 초당 0.8회) 게임 안에서 BPM을 확인할 수 없었습니다. 그래서 같은 알고리즘(AnalyserNode와 같은 FFT·블랙먼 창·dB→바이트 변환)을 Python으로 1~7.mp3에 돌려, 전체 곡 자기상관 기준값과 비교했습니다. `tools/tests/v53_bpm_tracker_sim.py`

| 곡 | 추적기(수렴값) | 기준값 |
|---|---|---|
| 1 | 134.1 | 133.3 |
| 2 | 135.1 | 136.4 |
| 3 | 122.2 | 122.4 |
| 4 | 110.1 | 111.1 |
| 5 | 110.5 | 109.1 |
| 7 | 123.9 | 125.0 |

곡 6은 시험 구간(90초) 안에서 곡이 끝나 수렴하지 못했습니다. 대체로 10~15초 안에 맞춰집니다.

## 3. 수정 후 측정 (실제로 돌린 시험)
| 기기 | JS 오류 | 가로 스크롤 | 화면 밖 | 겹침 | 작은 터치 영역 |
|---|---|---|---|---|---|
| 휴대폰 세로 | 0 | 없음 | 0 | 0 | 16 → **0** |
| 휴대폰 가로 | 0 | 없음 | 0 | 0 | 17 → **0** |
| 태블릿 세로 | 0 | 없음 | 0 | 1 → **0** | 22 → **0** |
| 태블릿 가로 | 0 | 없음 | 0 | 1 → **0** | 22 → **0** |
| 데스크톱 | 0 | 없음 | 0 | 0 | 0 |
| 울트라와이드 | 0 | 없음 | 0 | 0 | 0 |

- **실사 캐릭터 회귀 시험(데스크톱)**: 입장 40초 후 79/79명 그려짐(v52는 76). 클럽 곳곳 8번 이동해도 전원 표시, 투명 0명·옛 캐릭터 0명. 혜정 대화(LOD)→블루스(고해상도) 표시, 블루스·디스코 조명 = 전등만.
- **휴대폰 프로필**: 35/35명 그려짐(헤드리스 기준 약 60초, v52 약 100초). 허공에 뜬 잔 0개.
- **장시간 시험(약 7분, 이동·디스코·블루스 반복)**: JS 힙 397~421MB로 증가 추세 없음, 장면 객체·실사 목록 안정, 오류 0. 적응형 해상도가 실제로 동작함(20fps → 픽셀 비율 1.0 → 0.85).
- **시험 중 발견해 고친 회귀 1건**: 작업 중 `humanglb.js`의 주석이 `const acts = []`를 삼켜 **모든 인물이 안 그려지던** 상태를 회귀 시험이 잡았습니다. 수정 후 위 결과를 확인했습니다. 같은 실수가 두 번(v48·v53) 나와서 자동 검사 도구 `tools/tests/check_commented_code.py`를 추가했습니다(이전/현재 폴더를 비교해 주석에 갇힌 코드를 찾음, 현재 0건).

## 4. 남은 한계(솔직하게)
- 지시서의 모든 항목(친구 시스템, 평판 시스템, 공간 음향 전면 개편, 모든 UI 재디자인 등)을 이번에 구현하지는 않았습니다. 이미 있는 기능(디스코·블루스 타임, 골든벨, 노래방, VIP 룸, 화장실·흡연실, DJ 테이크오버, 샴페인 쇼, 웨이터·부킹, 접속자 목록·신고 등)과 겹치지 않으면서 안정적으로 넣을 수 있는 것만 넣었습니다.
- 실제 휴대폰·태블릿 기기에서는 시험하지 않았습니다(헤드리스 에뮬레이션만). 실제 GPU 성능·발열·메모리는 기기에서 확인이 필요합니다.
- 여러 명 동시 접속(멀티플레이) 부하 시험은 하지 않았습니다.
