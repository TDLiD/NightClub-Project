# 06. 음악 · 공간 음향(Spatial Audio) · 사운드 댐핑 로직

> 구현: `public/js/audio.js` (Web Audio) · `public/js/voice.js` (WebRTC 음성 공간화) · 호출: `main.js` 매 프레임 `NC.Audio.update(player, yaw, zone, doorOpen)`

## 1. 신호 흐름
```
[신스 디스코 118BPM] → musicBus ─┬→ Panner(HRTF, 스테이지 스피커 (0,2.6,-17.6)) → BassShelf(120Hz) ─┐
                                └→ BleedLP(350Hz) → BleedGain ──────────────────────────────────┴→ ZoneLP → ZoneGain ─┬→ Duck → MusicVol → Master → Compressor → 🔊
                                                                                                                    └→ Convolver(2.2s 리버브) → Wet ┘
[WebRTC 음성] → (사람별) Panner(HRTF, 상대 위치) → VoiceBus → Master         [효과음] → SfxBus → Master
```
- **직접음(Panner)**: 스테이지 스피커에서 나오는 소리. `inverse` 거리 모델(refDistance 7m, rolloff 1.1) → 스테이지에 가까울수록 커지고 방향감(HRTF)이 생김. AudioListener = 플레이어 귀(높이 1.6m), 방향 = 카메라 시선.
- **블리드(Bleed)**: 벽·바닥을 타고 퍼지는 저음. 350Hz 로우패스 → 어디서든 "쿵쿵"은 남음.
- **존 필터(ZoneLP/ZoneGain)**: 현재 구역에 따라 고음 차단·볼륨 감쇠 = 사운드 댐핑.
- **덕킹(Duck)**: 누군가 말하면(TTS·마이크·원격 음성 RMS > 0.04) 음악 −5dB.

| stage | 20 kHz | 1.00 | 0.16 | +7 dB (+거리 보너스 최대 +5) | 0.25 | 심장이 울리는 쿵쿵 |
| dance | 18 kHz | 0.95 | 0.15 | +4 dB | 0.30 | 풀 사운드 |
| hall (홀 중앙) | 12 kHz | 0.85 | 0.14 | +2 dB | 0.32 | |
| tables | 9 kHz | 0.78 | 0.12 | +1 dB | 0.35 | 대화 가능한 정도 |
| bar | 7 kHz | 0.72 | 0.10 | 0 | 0.35 | |
| corridor | 4.2 kHz | 0.62 | 0.10 | 0 | 0.40 | 한 겹 막힌 소리 |
| **vip (문 닫힘)** | **520 Hz** | **0.30** | 0.04 | −2 dB | 0.55 | 벽 너머 웅웅거리는 저음만, 목소리 또렷 |
| vip (문 열림) | 1.8 kHz | 0.50 | 0.06 | 0 | 0.50 | 문틈으로 새는 음악 |

### 스테이지 근접 보너스
```
near = max(0, 1 − 스피커까지거리 / 22m)
BassShelf.gain = zone.bass + near × 5 dB
```
→ 같은 댄스플로어 안에서도 앞쪽으로 갈수록 저음 압력이 커짐(패너 거리감쇠와 별개).

## 3. VIP 룸 사운드 댐핑 시퀀스
1. 플레이어가 룸 안(`world.vipAt`)에 들어오면 zone = `vip` → 0.25s 동안 로우패스가 18k→520Hz, 볼륨 0.95→0.3 으로 내려감.
2. 도어 열림 정도(`door.open > 0.5`)를 같이 보고 `vipOpen` 값으로 절반만 댐핑 → 문이 닫히는 순간 "툭" 하고 조용해지는 효과.
3. 같은 순간 `NC.emit('room', i)` → 서버 `zone` 메시지 → **채팅 범위가 룸으로 제한**, **WebRTC 음성도 룸 멤버끼리만 연결**(밖과의 연결은 끊음).
4. NPC 대사(TTS)·상대 음성이 들리면 덕킹 −5dB 추가 → 룸 안 대화가 확실히 앞으로 나옴.

## 4. 사람 목소리(WebRTC) 공간화
| 파라미터 | 값 | 이유 |
|---|---|---|
| panningModel | HRTF | 헤드폰에서 방향감 |
| distanceModel | inverse, refDistance 1.5m, rolloff 1.3, max 30m | 1.5m 안은 또렷, 멀어지면 빠르게 작아짐 |
| 연결 반경 | NEAR_RADIUS 8m (+3m 히스테리시스로 끊김 방지) | 서버에서도 동일 반경 검증 |
| 룸 규칙 | 룸 안팎 사람끼리는 연결 안 함 | 비밀 대화방 |

## 5. 구현 메모
- 브라우저 정책상 AudioContext 는 사용자 클릭(입장 버튼) 이후 생성/재개.
- Chrome 은 원격 WebRTC 스트림을 `<audio muted>` 요소에도 붙여야 WebAudio 로 소리가 흐름(voice.js 처리).
- 브라우저 TTS(speechSynthesis)는 WebAudio 그래프로 라우팅이 불가 → 공간화 대신 덕킹만 적용. 실제 서비스는 **서버 TTS(오디오 파일/스트림)** 를 받아 NPC 위치의 PannerNode 로 재생하는 구조를 권장.
- 실제 음원 사용 시: `musicBus` 앞에 `MediaElementSource`(라이선스 확보된 음원) 또는 스템(드럼/베이스/보컬) 별 소스를 두면 구역별로 스템 믹스를 다르게 할 수 있음(예: VIP에선 드럼·베이스만).
