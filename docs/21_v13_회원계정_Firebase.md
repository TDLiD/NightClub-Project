# v13 — 손님 · 로그인 · 회원가입 (Firebase Realtime Database)

## 1. Firebase 설정 (필수)
1. Firebase 콘솔 → Realtime Database → **규칙** 탭에 아래를 붙여 넣고 **게시**합니다.
```json
{
  "rules": {
    "users": {
      ".read": true,
      ".write": true,
      ".indexOn": ["id", "email", "nickname"]
    }
  }
}
```
   - `.indexOn`이 있으면 중복확인과 로그인이 해당 회원 1명만 조회합니다. 없어도 동작하지만, 전체 회원을 내려받아 비교하므로 느립니다.
2. DB 주소는 `auth.js`의 `DB` 상수에 들어 있습니다: `https://night-club-866bc-default-rtdb.asia-southeast1.firebasedatabase.app`
   - 서버 쪽 `/api/config`가 `firebaseUrl`을 주면 그 값을 우선합니다.
3. 별도 SDK나 API 키는 필요 없습니다(REST + fetch).

## 2. 데이터 구조
```json
"users": {
  "user_mh8x2k_ab12cd": {
    "id": "newbie01", "password": "(평문)", "email": "newbie@example.com",
    "nickname": "네온나비", "gender": "여성", "characterNo": 3, "createdAt": "2026-11-09T07:55:21Z"
  }
}
```
- `uid`는 `user_` + 시간 + 랜덤 문자열로 자동 생성합니다.
- `characterNo`는 성별별 스타일 번호(1~11)이며, 기본값은 항상 1입니다. 남성 No.1은 「강남 수트」, 여성 No.1은 「강남 클럽 퀸」입니다. 목록은 `entry.js`의 `STYLES` 순서와 같습니다.

## 3. 기능 목록
| 화면 | 기능 |
|---|---|
| 👤 손님 (기본) | 기존 닉네임·스타일 선택 후 「손님으로 입장하기」. 저장되지 않음 |
| 📝 회원가입 | 아이디: 영문 시작 4~16자, 중복확인 / 비밀번호: 6자↑, 대문자+소문자+숫자 필수, 특수문자 선택, 조건 칩 실시간 표시, 아이디 포함 금지 / 비밀번호 확인: 일치 검사 / 이메일: 형식 검사 + 중복확인 / 성별 / 닉네임: 2~10자 + 중복확인 / 캐릭터: 선택(갤러리), 기본 No.1 / 약관 동의(필수). 입력을 고치면 중복확인이 무효화되고, 제출 직전에 다시 확인하며, 저장 후 읽어서 검증 |
| 🔑 로그인 | 아이디·비밀번호, 👁 보기, 아이디 저장, Enter 제출, 실패 메시지(n/5), 5회 실패 시 30초 잠금 |
| 아이디 찾기 | 이메일 입력 → 아이디 전체를 팝업으로 표시 → 「로그인하러 가기」 |
| 비밀번호 찾기 | 이메일 입력 → 비밀번호를 끝 한 자리만 * 로 가려 팝업으로 표시 |
| 로그인 상태 | 「○○(으)로 입장하기」. 닉네임·성별·캐릭터가 계정 값으로 고정되며, 캐릭터 변경과 로그아웃 가능 |
| ⚙ 설정 (게임 중) | 「🧍 내 캐릭터 변경 (No.n)」 → 갤러리에서 선택 → DB 저장 + 게임 속 캐릭터 즉시 교체 |
| 오류 처리 | 네트워크 끊김, 10초 시간 초과, DB 규칙 거부(401/403), 동시 가입 충돌, 저장 검증 실패를 각각 안내 |

## 4. ⚠ 보안 안내 (반드시 읽어 주세요)
요청하신 스펙에 따라 **비밀번호를 평문으로 저장**하고, **비밀번호 찾기에서 끝 한 자리만 가려 보여 줍니다.** 그 결과 다음 위험이 있습니다.
- 중복확인을 위해 DB를 `.read: true`로 열어 두므로, **DB 주소만 알면 누구나 브라우저에서 `…/users.json`을 열어 전체 회원의 아이디·비밀번호·이메일을 볼 수 있습니다.**
- `.write: true`이므로 누구나 회원 정보를 수정하거나 지울 수 있습니다.
- 비밀번호 찾기는 이메일만 알면 되는데, 이메일도 공개돼 있어 사실상 누구나 남의 비밀번호를 알아낼 수 있습니다.
- 다른 사이트와 같은 비밀번호를 쓰는 회원은 그 계정까지 위험해집니다.

**권장 사항:** 테스트와 지인 대상 소규모 운영에만 쓰세요. 실제 서비스를 하려면 다음으로 바꾸시길 권합니다.
1. **Firebase Authentication**(이메일/비밀번호): 비밀번호를 Google이 안전하게 해시로 보관하고, 비밀번호 재설정 메일을 보냅니다.
2. DB 규칙을 `auth != null`로 바꾸고, 각 회원은 자기 데이터만 읽고 쓸 수 있게 제한합니다.
3. 비밀번호 찾기를 "표시"가 아니라 "재설정 메일 발송"으로 바꿉니다.

필요하시면 위 방식으로 전환하는 작업도 해 드릴 수 있습니다.
